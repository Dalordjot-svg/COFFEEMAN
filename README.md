# COFFEEMAN — Waiter System

Мобильная PWA для официантов и отдельная панель администратора. Интерфейс на русском языке. Пречек и завершение обслуживания фиксируют внутренние статусы заказа.

## Локальный запуск

Требуется Node.js 22.12+ и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. По умолчанию открывается пустое локальное рабочее пространство. Для работы с каталогом и настройками войдите как **admin**, для заказов используйте имя сотрудника. Вход с существующим именем восстанавливает профиль из локальной базы, включая имя из списка сотрудников. Пробелы и регистр при поиске имени учитываются одинаково. Новое имя создаёт отдельный профиль. Данные в IndexedDB и статусы присутствия синхронизируются между вкладками одного браузера.

Новые установки открываются с пустым каталогом, одним залом и столами 1–20. При переходе на эту планировку локальный каталог и остатки очищаются один раз, а отчёт начинается заново. Закрытые заказы остаются в истории.

## Рабочий режим

Прочитайте [инструкцию по Firebase](docs/firebase.md). В рабочем режиме доступ определяют Firebase Authentication, роли COFFEEMAN и состояние профиля сотрудника. Все операции приложения сохраняются в Realtime Database в пространстве `coffeeman/`. Браузер читает разрешённые коллекции. Проверенные изменения выполняет Cloud Function в транзакции. Для текущего проекта `gbank-838eb` требуется точный URL экземпляра Realtime Database из консоли и авторизованный доступ для настройки.

## Установка на телефон

На первом открытии в мобильном браузере COFFEEMAN показывает инструкцию для текущей платформы. Её можно открыть снова кнопкой «Как установить приложение». При запуске установленной PWA подсказка скрыта.

- **iPhone.** Откройте сайт в Safari, нажмите «Поделиться» → «На экран Домой» → «Добавить».
- **Android.** Откройте сайт в Chrome и выберите «Установить приложение». В некоторых версиях Chrome эта команда находится в «Добавить на главный экран».

После установки запускайте COFFEEMAN с иконки. Приложение открывается в отдельном окне. Для установки на физическом устройстве нужен HTTPS-адрес. Для проверки локальной сборки используйте `npm run build` и `npm run preview`.

## Публикация на GitHub Pages

[COFFEEMAN на GitHub Pages](https://dalordjot-svg.github.io/COFFEEMAN/) открывает собранное приложение из `site/`. Репозиторий настроен на публикацию из корня ветки `main`. Чтобы обновить сайт, выполните `npm run build:pages` и включите обновлённый `site/` в коммит. Режим опубликованной сборки задаётся теми же переменными, что и локальная сборка. Опубликованная версия сохраняет данные в браузере.

## Добавление блюд

Откройте **Каталог** в административной панели. Для одного блюда заполните форму добавления товара. Для нескольких блюд откройте импорт меню, скачайте инструкцию и передайте её вместе с исходным меню выбранному ИИ. Вставьте полученный JSON в COFFEEMAN, проверьте результат и подтвердите импорт.

Цены и категории проверяются перед записью. Импорт создаёт отсутствующие категории и сохраняет новые блюда одной операцией. Позиции с уже существующим названием в той же категории пропускаются, а действующие цены и остатки сохраняются. Для одинаковых названий из разных категорий создаются отдельные позиции.

## Рабочие сценарии

- Официант видит сводку за день и предупреждения, открывает заказы из карточек, работает со столами и именными табами. В редакторе позиции распределяются по гостям, а размер, модификаторы и комментарии сохраняются вместе с ценой на момент заказа.
- Отправка на кухню резервирует порции. Отмена освобождает резерв, выдача уменьшает физический остаток. Нулевой и минимальный остатки отражаются в стоп-листе. Независимая ручная блокировка сохраняется после пополнения.
- Администратор управляет товарами, категориями, залами, столами, сотрудниками, заказами и порогами предупреждений. Архивирование сохраняет историю. Операции изменения данных записываются в журнал. В разделе «Сотрудники» показано, кто сейчас подключён. Статус «В сети» показывает открытый сеанс приложения.
- Официант открывает список для кассы кнопкой «К расчёту» и закрывает заказ свайпом. Выручка рассчитывается по закрытым заказам. Валовая прибыль равна выручке за вычетом стоимости порций, зафиксированной при отправке заказа. Добавьте себестоимость в карточке блюда или полем `cost` при импорте. Личные показатели привязаны к идентификатору аккаунта. День, неделя и месяц определяются календарём в часовом поясе браузера.
- Приложение показывает состояние соединения. Ранее загруженная оболочка доступна офлайн. В рабочем режиме изменения требуют сети, чтобы подтвердить остатки и полномочия; в локальном деморежиме операции продолжают работать без сети.

## Проверка

```bash
npm test
npx playwright install chromium webkit
npm run test:e2e
npm run build
VITE_TEST_FIXTURES=1 npm run build
QA_PREVIEW=1 QA_WEBKIT=1 npm run test:e2e
```

Для тестов Firebase Auth, Realtime Database и Functions используйте команду Emulator Suite из [инструкции по Firebase](docs/firebase.md).

В [материалах визуальной проверки](docs/visual-qa.md) сохранены снимки экранов и размеры браузеров. Доступный визуальный референс — приложенный к заданию лист из 12 экранов.
